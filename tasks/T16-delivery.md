## T16. Сдать задание
Приоритет P0 · Оценка 0,5 ч · Зависит от T01–T11 · Покрывает: R22, R23, R24, R25, R26, R27, R28, R29, Q4, Q5, Q7

### 1. История пользователя
Как проверяющий, я хочу получить репозиторий, README, работающую demo-ссылку и переписку с AI,
чтобы за 5 минут запустить проект, понять, что сделано и почему, и проверить сценарии из demo-критерия.
Задача выполняется последней, после готовности всех P0-задач.

### 2. Границы
Входит: README; публикация demo; ссылка на репозиторий; приложенная переписка с AI; проверка
demo-критерия по чек-листу перед сдачей.
Не входит: новые функции (T01–T15); выбор стека и платформы публикации — решение разработчика (R22);
реальный бэкенд и авторизация (R21).

### 3. Бизнес-правила
1. Стек выбирает разработчик и называет его в README (R22, Q5).
2. Ограничение 4–6 часов снято; в README — фактическое время по каждой задаче и всего (R23, D30).
3. Не сделанное перечисляется в README с причиной; приоритеты P0/P1/P2 задают порядок (R24, D30).
4. Сдаются: репозиторий, README, deployed demo, переписка с AI (R25–R28).
5. Неясности закрывались вопросами; принятые решения D1–D36 перечислены или даны ссылкой (R29).
6. Отступления от контракта задания описаны: `roomId` в `Booking`, параметры `from`/`to`, вызовы
   `/api/rooms` и `/api/settings`, статус `422` с кодами (D21, D31, SPEC §13).
7. Слой API отделён от интерфейса: в README описано, как заменить mock на реальный сервер (Q4).
8. Данные mock общие для вкладок одного браузера и переживают перезагрузку; в другом браузере — свои (D18).
9. Начальные брони mock — прошлые и будущие, относительно даты первого запуска (D17).
10. Demo открывается по ссылке без входа (R21).

### 4. Сценарий
1. Разработчик заполняет README по разделам из пункта 9.
2. Публикует demo, открывает ссылку в чистом окне браузера → экран «Комнаты» с данными.
3. Проходит чек-лист раздела 11 на demo.
4. Прикладывает переписку с AI в репозиторий или ссылкой из README.
5. Передаёт проверяющему ссылку на репозиторий; в README есть ссылка на demo.
6. Проверяющий открывает README → запускает локально по инструкции или открывает demo.
7. Проверяющий проходит demo-критерий, включая R8 двумя вкладками.
   - 7а. Demo не открывается → README содержит команды локального запуска, проверка идёт локально.

2. Ссылки: репозиторий, demo, переписка с AI.
3. Статус задач: таблица T01–T16 — сделано / частично / не сделано, фактические часы, приоритет.
4. Итог времени: оценка 12,0 ч и фактическое (D30).
5. Отступления от контракта: `roomId`, `from`/`to` включительно, `/api/rooms`, `/api/settings`,
   `422` с кодами и `{ code, message, field? }` (D10, D21, D31).
6. Решения владельца: ссылка на таблицу D1–D36 или краткий список (R29).

### 11. Критерии приёмки
Чек-лист перед сдачей. Проверка в среду 2026-10-07, 14:10 по времени комнаты.
1. Дано: README. Когда: выполнить команды запуска на чистой копии. Тогда: приложение открывается.
2. Дано: demo-ссылка. Когда: открыть в окне без истории. Тогда: экран «Комнаты» без входа, есть брони.
3. Дано: README. Тогда: таблица T01–T16 со статусом и часами, итог фактического времени.
4. Дано: README. Тогда: раздел отступлений от контракта называет `roomId`, `from`/`to`, `/api/rooms`,
   `/api/settings`, `422`.
5. Дано: README. Тогда: есть ссылка или список решений D1–D36.
6. Дано: две вкладки на одной комнате, 2026-10-08. Когда: занять 15:00–15:30 в первой, сохранить то же
   во второй. Тогда: во второй «Это время уже занято…», сетка обновлена, форма на месте.
7. Дано: demo. Когда: открыть прошлую дату 2026-10-01. Тогда: брони видны, создание недоступно.
8. Дано: demo. Когда: сохранить 10:00–11:00 при брони 11:00–12:00 на 2026-10-08. Тогда: сохранено.
9. Дано: прямой запрос к mock с `start=10:15`. Тогда: `422 OFF_GRID`.
10. Дано: окно 360 px. Когда: создать бронь с клавиатуры. Тогда: бронь создана, страница не прокручивается
    по горизонтали.
11. Дано: README. Тогда: описано, где задаётся адрес сервера и как отключить mock.
12. Дано: репозиторий. Тогда: переписка с AI приложена или доступна по ссылке из README.
