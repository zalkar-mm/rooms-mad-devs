# Спринт «Бронирование переговорных»

## Цель спринта

Сотрудник находит свободную переговорную, бронирует её на 30–120 минут в рабочий день, меняет и отменяет
бронь. Правила R1–R8 соблюдаются на клиенте и на сервере, интерфейс не теряет введённые данные при
конфликте и сбоях. Слой API отделён от интерфейса и заменяется реальным бэкендом без правки экранов.

## Demo-критерий

На deployed demo проверяющий за 5 минут:
1. открывает список комнат и видит состояние «сейчас» и «в ближайший час»;
2. открывает комнату, листает дни и недели, видит прошлые и будущие брони;
3. создаёт бронь двойным нажатием и протягиванием, меняет её, удаляет с подтверждением;
4. получает отказ на каждое из правил R1–R7 — на клиенте и при прямом запросе к серверу;
5. открывает две вкладки, занимает слот в первой, сохраняет тот же слот во второй — видит `409`,
   обновлённую сетку и сохранённую форму (R8);
6. сужает окно до 360 px и проходит сценарий создания с клавиатуры.

## Документы

- `../SPEC.md` — описание системы для дизайна: экраны, правила, тексты, контракт.
- `T01…T16` — задачи спринта. Каждая ссылается на правила `R`, требования `Q` и решения `D` ниже.

## Решения владельца

«Владелец» — решение из ответа. «По умолчанию» — рекомендация аналитика, принятая ответом «на твоё усмотрение».

| № | Решение | Тип |
|---|---|---|
| D1 | Отображение — календарная сетка по времени. Виды «День», «Неделя», «Месяц» | владелец |
| D2 | Комнат несколько. Стартовый экран — карточки комнат | владелец |
| D3 | Шаг времени 30 минут. Двойное нажатие на свободный слот — черновик 30 минут, протягивание — 30–120 минут | владелец |
| D4 | `title` обязателен, 1–60 символов после обрезки пробелов. Свободный ввод и подсказки из справочника настроек | владелец + по умолчанию (длина) |
| D5 | Просмотр — 30 дней назад, бронирование — 30 дней вперёд от сегодня. Значения из настроек | владелец |
| D6 | Прошедшая бронь — `end ≤ сейчас` | владелец |
| D7 | Сегодня `start ≥` ближайшая граница слота не раньше «сейчас». После 17:30 на сегодня бронировать нельзя | владелец + по умолчанию |

| D19 | При возврате на вкладку перезапрашиваются брони видимого периода и карточки комнат | владелец |
| D20 | Ширина от 360 px до десктопа. На телефоне по умолчанию вид «День» | владелец |

| D22 | Время показывается в поясе комнаты с подписью пояса. «Сейчас» — время сервера из настроек | по умолчанию |
| D23 | Переключатель «Моё время» показывает время в поясе устройства. По умолчанию — время комнаты | по умолчанию |

| D30 | Ограничение 4–6 часов снято владельцем. Приоритеты задают порядок работ, в README — фактическое время | владелец |
| D31 | Нарушения правил R1–R4, R6 и D-правил сервер отклоняет со статусом `422` и кодом из `SPEC.md`, раздел 9 | по умолчанию |

## Открытые вопросы

1. Кому обращаться при сбое сервера: имя или канал администратора для текста D15 не известны.
2. Можно ли менять окончание идущей брони — укоротить или продлить (сейчас запрещено, D25).
3. Без авторизации любой посетитель меняет и удаляет любую будущую бронь. Нужна ли пометка «кто создал».

Вопросы уровня одной задачи собраны в разделе 13 каждой задачи, у большинства записан вариант по умолчанию.
Главные из них:
- T02: код ответа для пропущенного поля и времени не в формате `HH:mm`; ответ `GET` за горизонтом просмотра.
- T06: текст пересечения на клиенте до отправки (черновик); как сдвигается «Окончание» при смене «Начала».
- T07: протягивание вверх (по умолчанию разрешено, якорь — первый слот).
- T08: подсказка заменяет текст поля или дописывается (по умолчанию заменяет).
- T09: после T12 вкладка сама обновляет брони при возврате, поэтому `409` удобнее показывать на двух окнах рядом.
- T10: можно ли переносить бронь в другую комнату (сейчас нельзя, D9 комнату не называет).
- T13: перезапрашивать брони карточек каждую минуту или только пересчитывать по «сейчас».
- T15: сетка при большом сдвиге пояса, когда рабочий день комнаты пересекает местную полночь; пояса со сдвигом не кратным 30 минутам.
