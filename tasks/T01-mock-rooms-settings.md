## T01. Отдать комнаты и настройки из mock API
Приоритет P0 · Оценка 0,5 ч · Зависит от — · Покрывает: R9, R17, R18, R20, R21, Q4

### 1. История пользователя
Как разработчик интерфейса, я хочу получать список комнат и все настройки системы с mock-сервера через
отдельный слой данных, чтобы экраны не содержали зашитых значений и переходили на реальный бэкенд без правки.
Как проверяющий, я хочу открыть ответы `GET /api/settings` и `GET /api/rooms` и увидеть в них все параметры
из `SPEC.md`, раздел 4. Задача первая в спринте: на её ответах строятся все экраны.

### 2. Границы
Входит:
- `GET /api/settings` — все параметры из `SPEC.md`, раздел 4, включая `serverNow` и `timezone`;
- `GET /api/rooms` — список комнат в начальных данных;
- единый формат ответа об отказе `{ code, message, field? }` и ответ `404 ROOM_NOT_FOUND`;
- слой данных: единственное место, через которое экраны получают комнаты и настройки;
- поведение слоя данных при сбое сети и ответе `5xx`.

Не входит (и где будет):
- брони, их хранение и проверки правил — T02;
- экраны, состояния загрузки и сбоя в интерфейсе — T03 (календарь), T13 (список комнат);
- описание отступлений от контракта задания в README — T16.

### 3. Бизнес-правила
1. Интерфейс не зашивает рабочие часы, шаг, длительности, горизонт, выходные, длину и подсказки названия —
   всё приходит из `GET /api/settings` (D35, D17).
2. Значения mock-сервера: `timezone` = `Asia/Bishkek`; `workdayStart` = `09:00`; `workdayEnd` = `18:00`;
   `slotMinutes` = `30`; `minDurationMinutes` = `30`; `maxDurationMinutes` = `120`; `bookingHorizonDays` = `30`;
   `historyDays` = `30`; `workingWeekdays` = `[1,2,3,4,5]`; `titleMaxLength` = `60`; `titleSuggestions` =
   «Созвон», «Встреча», «Работа в тишине», «Собеседование», «Планирование» (SPEC §4, D35, D5, D24, D4, D3).
3. Рабочий день — 09:00–18:00 во времени комнаты (R9, D22).
4. `serverNow` — время сервера на момент ответа в ISO-формате; это единственный источник «сейчас» (D22).
5. Комната — объект `{ id, name }` (D21). Порядок комнат в ответе — порядок показа (SPEC §6.1).
6. Начальные данные — три комнаты: «Переговорная 1», «Переговорная 2», «Переговорная 3» (по умолчанию, D17).
7. Ответ об отказе — `{ code, message, field? }`; интерфейс показывает `message`, при пустом — текст по `code`
   (D10).
8. Обращение к несуществующей комнате — `404` с кодом `ROOM_NOT_FOUND` (SPEC §9).
9. Сетевой слой отделён от интерфейса: экраны получают данные только через слой данных (R20, Q4).
10. Бэкенда и авторизации нет: сервер — mock, запросы без входа в систему (R21, R17).
11. Контракт задания расширяется вызовами `/api/rooms` и `/api/settings` (R18, D21).

### 4. Сценарий
1. Экран запрашивает настройки у слоя данных → слой данных выполняет `GET /api/settings` → сервер отвечает
   `200` и объектом настроек → экран получает объект целиком.
2. Экран запрашивает комнаты → `GET /api/rooms` → `200` и массив из трёх комнат в порядке начальных данных.
3. Экран запрашивает данные комнаты с неизвестным `id` → сервер отвечает `404`
   `{ code: "ROOM_NOT_FOUND", message: "Эта переговорная не найдена. Вернитесь к списку комнат" }`.
4. Альтернатива — сеть недоступна или сервер ответил `5xx`: слой данных отдаёт экрану признак «сервер
   не отвечает» без `code`; экран показывает «Сервер не отвечает. Попробуйте ещё раз через минуту».
5. Альтернатива — проверяющий меняет адрес сервера в настройке слоя данных: экраны продолжают работать
   без правки, запросы уходят на новый адрес.

### 5. Состояния экрана
Экранов в задаче нет. Состояния описывают, что слой данных отдаёт экрану.

| Состояние | Что получает экран | Что доступно экрану | Текст |
|---|---|---|---|
| Запрос выполняется | Признак ожидания | Показать заготовку (T03, T13) | — |
| Успех настроек | Объект настроек со всеми полями §4 | Строить сетку и правила | — |
| Успех комнат | Массив `{ id, name }` | Показать комнаты | — |
| Пустой список комнат | Пустой массив | Показать пустое состояние (T13) | Переговорных пока нет |
| Отказ сервера | `{ code, message, field? }` | Показать `message` | По `code`, SPEC §9 |
| Сбой сети, `5xx` | Признак «сервер не отвечает» | Повторить запрос | Сервер не отвечает. Попробуйте ещё раз через минуту |

### 6. Валидация
| Поле / условие | Где проверяется | Когда показывается | Текст |
|---|---|---|---|
| `id` комнаты существует | Сервер | При запросе данных комнаты | Эта переговорная не найдена. Вернитесь к списку комнат |
| Ответ настроек содержит все поля §4 | Слой данных | При получении | Настройки не загрузились. Проверьте подключение и нажмите «Повторить» (черновик) |

### 7. Ошибки сервера
| Ответ | Что видит пользователь | Что со списком | Что с введёнными данными | Действия |
|---|---|---|---|---|
| `404 ROOM_NOT_FOUND` | Эта переговорная не найдена. Вернитесь к списку комнат | Не показывается | Нет ввода | «Все комнаты» (T13) |
| `5xx` | Сервер не отвечает. Попробуйте ещё раз через минуту | Прежние данные остаются | Нет ввода | «Повторить» |
| Сеть недоступна | Тот же текст, что для `5xx` | Прежние данные остаются | Нет ввода | «Повторить» |
| Отказ без `message` | Текст по `code` из SPEC §9 | — | — | По `code` |

### 8. Граничные случаи
| Случай | Ожидаемое поведение | Источник |
|---|---|---|
| Граница рабочего дня | `workdayStart` = `09:00`, `workdayEnd` = `18:00`, формат строго `HH:mm` | R9, SPEC §4 |
| `serverNow` в 23:59 по UTC = 05:59 следующего дня в поясе комнаты | «Сегодня» считается в поясе комнаты | D22 |
| Два запроса настроек подряд | `serverNow` во втором ответе не раньше, чем в первом | D22 |
| `message` пустой | Экран показывает текст по `code` | D10 |
| `field` отсутствует | Отказ не привязан к полю | D10 |
| `id` комнаты с пробелами или пустой | `404 ROOM_NOT_FOUND` | SPEC §9 |
| В ответе комнат одна комната | Порядок и формат те же | SPEC §6.1 |
| Значение настройки изменено на сервере | Интерфейс берёт новое значение без правки экранов | D35 |

### 9. Данные и контракт
- `GET /api/settings` → `200`, объект с полями `timezone`, `workdayStart`, `workdayEnd`, `slotMinutes`,
  `minDurationMinutes`, `maxDurationMinutes`, `bookingHorizonDays`, `historyDays`, `workingWeekdays`,
  `titleMaxLength`, `titleSuggestions`, `serverNow` (SPEC §4, §13).
- `GET /api/rooms` → `200`, `Room[]`, `Room { id, name }` (D21).
- Отказ: `{ code, message, field? }`; `404` — `ROOM_NOT_FOUND` (SPEC §9, §13).
- `workingWeekdays` — номера дней недели, 1 — понедельник, 7 — воскресенье.
- Адрес сервера задаётся в одном месте слоя данных; экраны адрес не знают.

### 10. Доступность и адаптив
- Экранов в задаче нет. Слой данных отдаёт экрану `message` текстом, пригодным для объявления читалке
  без перевода фокуса (SPEC §12).
- Тексты отказов не зависят от ширины экрана.

### 11. Критерии приёмки
1. Дано: mock-сервер запущен. Когда: проверяющий открывает ответ `GET /api/settings`. Тогда: в нём
   12 полей из SPEC §4 со значениями из правила 2.
2. Дано: сейчас 14:10 в поясе комнаты, сегодня среда 2026-10-07. Когда: открыть ответ `GET /api/settings`.
   Тогда: `serverNow` соответствует 2026-10-07 14:10 по `Asia/Bishkek` (08:10 по UTC).
3. Дано: начальные данные. Когда: открыть ответ `GET /api/rooms`. Тогда: три комнаты в порядке
   «Переговорная 1», «Переговорная 2», «Переговорная 3», у каждой `id` и `name`.
4. Дано: комнаты с `id` `unknown` нет. Когда: запросить данные этой комнаты. Тогда: `404`,
   `code` = `ROOM_NOT_FOUND`, `message` = «Эта переговорная не найдена. Вернитесь к списку комнат».
5. Дано: исходный код интерфейса. Когда: найти в нём строки `09:00`, `18:00`, `30` как настройки и
   «Переговорная 1». Тогда: они встречаются только в mock-сервере, не в экранах.
6. Дано: исходный код. Когда: найти обращения по адресу `/api/`. Тогда: они есть только в слое данных.
7. Дано: адрес сервера в слое данных изменён на другой. Когда: открыть интерфейс. Тогда: запросы уходят
   на новый адрес, правок в экранах не было.
8. Дано: сеть отключена в браузере. Когда: экран запрашивает настройки. Тогда: экран получает признак
   «сервер не отвечает» и может повторить запрос; приложение не останавливается.
9. Дано: отказ сервера без `message`. Когда: он доходит до экрана. Тогда: экран получает текст по `code`.
10. Дано: `titleMaxLength` на сервере изменён на `40`. Когда: перезапросить настройки. Тогда: ответ
    содержит `40`, интерфейс использует `40` без правки экранов.

### 12. Для дизайнера
- Экранов нет. Тексты, которые эта задача отдаёт экранам: «Эта переговорная не найдена. Вернитесь к списку
  комнат», «Сервер не отвечает. Попробуйте ещё раз через минуту», «Переговорных пока нет».
- Названия комнат приходят с сервера: макеты должны выдерживать название до 60 символов (открытый вопрос 3).
- Не должно появляться: зашитые часы работы, шаг, длительности и подсказки в макетах как постоянные.

### 13. Открытые вопросы
1. Как интерфейс отсчитывает «сейчас» между запросами: по разнице `serverNow` и часов устройства,
   зафиксированной при загрузке настроек, или перезапросом настроек раз в минуту.
2. Нужен ли способ задать «сейчас» mock-сервера для проверки (например, 2026-10-07 14:10), чтобы критерии
   с конкретным временем проверялись в любое время суток.
3. Есть ли предел длины `name` комнаты; в начальных данных названия короткие.
4. Какой текст показывать, если ответ настроек пришёл без части полей; сейчас — черновик в разделе 6
   «Настройки не загрузились…», в SPEC такого текста нет.
