# Бронирование переговорных

SPA для бронирования переговорных комнат: тестовое задание Frontend Engineer.
Что делает система — [`SPEC.md`](./SPEC.md), задачи спринта — [`tasks/`](./tasks/README.md),
правила кода — [`AGENTS.md`](./AGENTS.md) и [`docs/`](./docs).

Бэкенда нет: запросы обслуживает mock API на MSW в браузере ([`docs/mocks.md`](./docs/mocks.md)).

## Запуск

Нужен Node.js 22 или новее.

```bash
npm install
cp .env.example .env    # включает mock API
npm run dev             # http://localhost:5173
```

## Переменные окружения

| Переменная | По умолчанию | Значение |
|---|---|---|
| `VITE_API_BASE_URL` | `/api` | Базовый URL API |
| `VITE_API_MOCK` | `false` | `true` — перед рендером запускается MSW и перехватывает запросы к API |

Переменные проверяются Zod при старте (`src/shared/config/env.ts`). Переход на реальный бэкенд —
`VITE_API_MOCK=false` и его адрес в `VITE_API_BASE_URL`, экраны не меняются.

## Структура `src/`

Feature-Sliced Design, импорт только вниз по слоям ([`docs/architecture.md`](./docs/architecture.md)):

```
src/
├── app/        точка входа, провайдеры, роутер, стили и токены
├── pages/      экраны: rooms (/), room (/rooms/:roomId), ui-kit (/ui-kit, только dev)
├── widgets/    блоки экрана
├── features/   пользовательские сценарии
├── entities/   settings, room, booking: контракт, API, правила
├── shared/     api-клиент, config, consts, lib, ui-кит
└── mocks/      mock API на MSW, вне FSD, импортируется только из app
```

## UI kit

- **Токены** — `src/app/styles/tokens.css`: цвета, шрифт Commissioner, текст `caption/small/body/title`,
  радиусы `radius-s/m`, тени `shadow-1/2`, ширина `xl` = 1200, `.bg-hatch`, кольцо фокуса `focus-ring`.
  Стандартная палитра Tailwind отключена, тёмной темы нет.
- **Компоненты** — кит в `src/shared/ui/*.tsx` и доменные в `entities/*/ui`, `widgets/*/ui`,
  `features/*/ui`. Все презентационные: данные через пропсы и слоты, события через колбэки.
  Код примитивов shadcn (Radix, react-day-picker, sonner) влит в кит-компоненты и правится как наш;
  сами пакеты импортируются только внутри `shared/ui` ([`docs/ui.md`](./docs/ui.md) §3).
- **`/ui-kit`** — страница проверки, только в dev (`npm run dev` → http://localhost:5173/ui-kit): каждый
  компонент во всех состояниях. hover и focus показаны принудительно атрибутом `data-state` на обёртке.
  В прод-сборку не попадает.

## Стек

React 19 + TypeScript 5.8 + Vite 6, React Compiler. Маршруты — react-router 7, состояние адреса (вид, дата,
открытая бронь, пояс) — nuqs. Серверные данные — TanStack Query 5 поверх одного axios-клиента, ответы
проверяет Zod. Форма — react-hook-form + Zod. Черновик брони и служебные флаги mock — Zustand. Даты —
date-fns + @date-fns/tz. UI — Tailwind CSS 4 и свой кит на Radix (код shadcn влит в компоненты кита).
Mock API — MSW 2 в браузере. Полный список и правила — [`AGENTS.md`](./AGENTS.md) §1.

## Отступления от контракта задания

- `Booking` содержит `roomId`: комнат несколько (D2, D21).
- `GET /api/bookings` принимает `roomId` и либо `date=YYYY-MM-DD`, либо `from` и `to` включительно — для
  недели и месяца одним запросом (D21). Ответ по `date`, затем `start` (D32).
- Новые вызовы `GET /api/rooms` и `GET /api/settings`: комнаты и все настройки (рабочий день, шаг,
  длительности, горизонт, выходные, длина и подсказки названия, пояс, `serverNow`) приходят с сервера,
  интерфейс их не зашивает (D21, D35).
- Нарушения правил — `422` с кодом из SPEC §9; конфликт — `409 CONFLICT`; нет брони или комнаты — `404`
  (D31). Тело отказа — `{ code, message, field? }`; интерфейс показывает `message`, при пустом — текст
  по `code` (D10).

## Решения владельца

Таблица D1–D36 — в [`tasks/README.md`](./tasks/README.md#решения-владельца). Ответы на открытые вопросы
задач, принятые по умолчанию, перечислены в телах коммитов и в «Что не сделано».

- «Моё время» показывается, только если рабочий день комнаты на видимых датах целиком на той же местной
  дате и смещение кратно 30 минутам; иначе (UTC−5, UTC+5:45) — только «Время комнаты» (T15, вопросы 2–3).
- Экран «Комнаты» показывает время комнаты и подписывает пояс над карточками, режим «Моё время» на него
  не действует (T15, вопрос 5). Тексты с числами из настроек строятся от настроек (D35).

## Как проверить

**Конфликт `409` (R8).** Откройте одну комнату и одну дату в двух окнах рядом. В первом создайте бронь
на 15:00–15:30. Во втором, не переключаясь в него, откройте тот же слот (двойное нажатие), введите
название и нажмите «Сохранить» — придёт `409`: сообщение в панели, сетка перезапрошена, чужая бронь
выделена, форма на месте. Если второе окно получит фокус раньше, оно само обновит брони (D19) и не даст
выбрать занятый слот — поэтому окна рядом. Конфликт в одной вкладке — служебная панель mock API
(колба в левом нижнем углу): «Конфликт 409 при сохранении».

**Отказы сервера в обход интерфейса.** В консоли браузера на demo:

```js
await fetch("/api/bookings", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ roomId: "r1", date: "2026-10-08", start: "10:15", end: "11:00", title: "Тест" }),
}).then((r) => r.json()) // { code: "OFF_GRID", … }
```

Так проверяются все коды R1–R7 (T02 §11). `404` — удалите открытую бронь во второй вкладке.

**Клавиатура и 360 px.** Сузьте окно до 360 px. Tab: «Перейти к календарю» → шапка → сетка (доступные
ячейки и брони по времени) → панель. Enter на доступной ячейке — черновик, Enter на «Сохранить» —
бронь. Esc закрывает панель, во время протягивания — отменяет его.

**Свой пояс.** Если пояс устройства не UTC+6, в шапке есть «Моё время» (T15).

## Замена mock на реальный сервер

Адрес сервера — одна переменная `VITE_API_BASE_URL` (`src/shared/config/env.ts`), её читает единственный
axios-клиент (`src/shared/api/axios-client.ts`). Экраны получают данные только через хуки
`src/entities/*/api`. Mock отключается `VITE_API_MOCK=false`: MSW не запускается, служебная панель не
монтируется. Правок в интерфейсе не нужно.

## Ограничения mock API

- Данные в `localStorage` этого браузера: общие для вкладок и переживают перезагрузку (D18), в другом
  браузере — свои. Сброс к начальным — очистка данных сайта.
- Начальные брони считаются от даты первого запуска: прошлые и будущие на рабочие дни вокруг неё (D17).
- Авторизации нет: любой посетитель меняет и удаляет любую будущую бронь (SPEC §2).
- Служебная панель: «Конфликт 409» и «Сбой 503» на один запрос. Запросы чтения TanStack Query повторяет
  один раз (`retry: 1`), поэтому одиночный «Сбой 503» на чтении не виден — он виден на сохранении
  и удалении.
