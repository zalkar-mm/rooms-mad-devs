# Workflow — git, коммиты, проверки

## 1. Ветки

- Работа — только в `main`, коммитами прямо в неё. Feature-веток нет.
- `main` всегда зелёная: каждый коммит проходит проверки §5.

## 2. Conventional commits

`<type>(<scope>?): <subject>` — на английском, в настоящем времени, без точки в конце.

Типы: `feat`, `fix`, `chore`, `docs`, `refactor`, `style`, `perf`.

Примеры:
- `chore: scaffold vite react-ts app`
- `feat(booking): add booking rules`
- `feat(mocks): serve bookings with rule checks`
- `docs(agents): document mocks layer`

Тело — что и почему, если не очевидно из заголовка. Новая зависимость вне `AGENTS.md` §1 — причина в теле.

## 3. Иерархия работы

- **Задача** = серия коммитов в `main`. **Этап** = коммит: одно осмысленное завершённое изменение. **Шаг** — внутри этапа,
  отдельно не коммитится.

### Размер этапа
- 5–200 строк диффа; больше — дробим, меньше 5 — объединяем с соседним.
- **Вне лимита:** сгенерированное без ручных правок — скаффолд Vite, `package-lock.json`,
  `public/mockServiceWorker.js`.
- Каждый этап проходит `lint + typecheck + build`. Ломает сборку «до следующего этапа» — плохой этап.

### Порядок этапов фичи
1. `AGENTS.md` / `docs/*.md` — только если задача явно вводит правило, первым коммитом.
2. Контракт: `entities/<entity>/model/*.types.ts`, схемы.
3. Правила: `entities/<entity>/lib/*`.
4. Mock-обработчик (`src/mocks/handlers`).
5. `entities/<entity>/api/`: `keys` → `repository` → хуки.
6. UI: `entities/*/ui` → `features/*` (`model` → `ui`) → `widgets` → `pages`.
7. Состояния: загрузка, пусто, ошибка, отправка, `409`, `404`.
8. Доступность и адаптив: клавиатура, `announce`, 360/768/1200, нет горизонтальной прокрутки.

## 4. Правки правил (`AGENTS.md`, `docs/*.md`)

- Только по явной задаче на это. Коммит `docs(...)`, первым в задаче, отдельно от кода.
- Решение всплыло по ходу задачи → не меняешь правило молча: флагаешь владельцу.
- `SPEC.md`, `tasks/`, PDF задания — не правим никогда.

## 5. Проверки перед коммитом

```bash
npm run lint        # eslint . --max-warnings 0
npm run typecheck   # tsc -b
npm run build       # tsc -b && vite build
```

Все три — без ошибок. Красный результат — не коммитим.

## 6. Тесты

Автотестов нет (решение владельца). Тестовые фреймворки и Storybook не ставим. Проверка — руками в
браузере по критериям приёмки задачи; что не проверено в браузере — так и пишется в отчёте.

## 7. Self-review перед коммитом

### P0 — блокеры
- `any`, `enum`, `index.*`, импорт вверх или кросс-слайс.
- HTTP вне `entities/*/api`; серверные данные вне TanStack Query.
- Правило брони вне `entities/booking/lib` или его копия.
- «Сейчас» в обход часов (`docs/data.md` §7).
- Тернарка, `&&` или инлайн-стрелка в JSX.
- Хардкод роута, ключа запроса, настройки, цвета.
- Текст интерфейса не из SPEC; окно поверх страницы.
- Потеря значений формы после `409`/`5xx`/сети.

### P1 — в этой же задаче
- Файл > 300 строк; компонент с > 3 `useEffect`.
- Нет состояния загрузки/пусто/ошибки/отправки.
- Дубликат логики во втором месте.
- Профилактическая мемоизация.

### Не флагаем
- Решения, задокументированные в `AGENTS.md` / `docs/*.md`.

## 8. Расхождения

1. Код против правил → правило важнее, флагни.
2. Правило против правила или SPEC → спроси владельца.
3. Правила против фактического стека → предложи правку `docs/` отдельным коммитом.
